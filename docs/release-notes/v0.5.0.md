# forge-kit v0.5.0

The first public release of forge-kit, a Claude Code plugin marketplace for people who plan with Claude in the app and build with Claude Code. This release is marketplace 0.5.0, with **code-handoff 0.4.0** and **idea-forge 0.4.0**.

## Highlights
- **code-handoff: no more screenshots between your planning chat and Claude Code.**
  - After every Claude Code turn, a Stop hook writes `.claude/handoff/last.md`: the prompt, progress notes, final reply, files changed, commands run and errors.
  - In the Claude app, `/code-handoff` reads it, walks you through anything only you can do, and writes the next prompt. Claude Code runs it with `/code-handoff:next`.
- **idea-forge: from idea to a project that's ready to build.**
  - `/idea-council` judges the idea with independent critics, an advocate and a judge.
  - `/idea-refine` turns it into an approved concept.
  - `/idea-launch` writes the full documentation set, with traceable requirement IDs and an independent review by fresh agents.
  - `/idea-code-setup` prepares CLAUDE.md, settings, a commit-and-push git guard and a kickoff prompt.
- **Windows, macOS, Linux and WSL.** On Windows, the hooks run in Windows PowerShell 5.1. Elsewhere they run in Node 18 or later, with no packages. One hook command picks the right version, under Git Bash, PowerShell or `sh`.
- **Tested:**
  - 49 Pester tests and about 70 node:test tests, in CI on `windows-latest`, `ubuntu-latest` (Node 18 and 22) and `macos-latest`
  - a parity test that both handoff versions write the same `last.md`
  - tests of the exact hook command that ships
- **Robust to real setups:**
  - Duplicate Stop hook runs and double installs (plugin plus installer, or an old per-project copy) still write each turn once.
  - Stale hook entries and leftovers are noted in `hook-error.log`. Nothing is deleted for you.

## Install

**Claude Code:**
```
/plugin marketplace add bawanallahbilyaminu/forge-kit
/plugin install code-handoff@forge-kit
/plugin install idea-forge@forge-kit
```
Then run `/reload-plugins`.

**Claude app (planning side):** download `code-handoff.plugin` and `idea-forge.plugin` below and install them in the app. Then connect your projects folder, or a project's `.claude` folder, in each planning chat.

**Windows without the plugin system:** use `installers/windows/install.ps1`, described in the code-handoff README. Don't use both the installer and the plugin.

## Platform support
| Platform | code-handoff hook | idea-forge git guard | Needs |
|---|---|---|---|
| Windows, with Git Bash | `handoff.ps1` | `git-guard.ps1` | Windows PowerShell 5.1, which is built in |
| Windows, without Git Bash | `handoff.ps1` | `git-guard.ps1` | The same |
| macOS, Linux, WSL | `handoff.mjs` | `git-guard.mjs` | Node 18 or later on the PATH |

Without Node, the hooks on macOS, Linux and WSL exit quietly and do nothing.

## Known issues
- The Claude app can't write inside a project's `.claude/` folder unless that folder itself is connected. `/idea-code-setup` therefore stages its files in `setup/dot-claude/`, and the kickoff prompt has Claude Code move them into place.
- **Real-world testing** has been on Windows: the plugin, the installer and the double-install guard, in daily use. On macOS, Linux and WSL the hooks are covered by CI tests, including the exact hook command, but not yet by daily use. Reports are welcome.
- **On macOS, Linux and WSL, the hooks need Node.** A missing Node isn't reported, because the hooks never break a session. Run `node --version` if turns aren't being written.
- **The README has diagrams but no GIF yet.** A GIF of the loop will follow.
